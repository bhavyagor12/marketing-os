# Marketing OS — Setup & Run

Everything you need to get the platform running locally, and what to plug in for each feature as the roadmap progresses.

---

## 1. One-time setup

**Install prereqs:**
- **Node 20+** — `nvm install 20 && nvm use 20`
- **pnpm 9** — `corepack enable && corepack prepare pnpm@9.12.0 --activate`
- **Docker Desktop** (for Postgres, Redis, MinIO)
- **uv** — `brew install uv` (or `curl -LsSf https://astral.sh/uv/install.sh | sh`) — for the Python agents service

**Then from the repo root:**

```bash
make setup
```

This runs end-to-end:
- Verifies tooling
- Generates `.env` and `apps/agents/.env` with fresh secrets
- `pnpm install` + creates the Python venv
- `docker compose up -d` (Postgres + Redis + MinIO)
- Creates the MinIO bucket
- Applies the full DB schema (pgvector extension + all tables)
- Symlinks `apps/web/.env.local → .env` so Next.js picks up root env

Idempotent — safe to re-run. To nuke volumes and start clean: `make reset`.

---

## 2. Running the app

```bash
make start
```

Three services come up together (color-prefixed logs):

| Service | URL | Role |
| --- | --- | --- |
| `web` | http://localhost:3000 | Next.js app, auth, server actions, tracking endpoints |
| `agents` | http://localhost:8000 | Python + FastAPI + LangGraph agents |
| `worker` | — | BullMQ — publish, brand ingestion, analytics |

Plus Docker:

| Service | URL | Role |
| --- | --- | --- |
| Postgres | `localhost:5432` | Data + pgvector |
| Redis | `localhost:6379` | BullMQ |
| MinIO | http://localhost:9001 (console, `minioadmin`/`minioadmin`) | S3-compatible object storage |

Ctrl-C to kill all three services cleanly. `make stop` stops Docker.

## 3. What to plug in — feature by feature

Everything below is independent. Fill only what you need to unlock a feature.

### A. Anthropic API key — required for ANY agent to run

Add **through the UI**, not `.env`:

1. Sign up / sign in
2. Dashboard → **Connections**
3. Click **Add key**
4. Paste an `sk-ant-...` key from https://console.anthropic.com/settings/keys
5. Done. Agents auto-pick up the key on their next call. Encrypted at rest with AES-256-GCM.

> Dev shortcut: set `ANTHROPIC_API_KEY` in `apps/agents/.env` as a fallback. The agent client prefers the DB key; env is only used if no DB key exists.

### B. X (Twitter) publishing — P0-2

1. https://developer.x.com/en/portal/dashboard → create Project + App
2. **User authentication settings** → Enable OAuth 2.0
3. Type: **Confidential client**
4. Callback URL: `http://localhost:3000/api/connections/x/callback`
5. Scopes: `tweet.read`, `tweet.write`, `users.read`, `offline.access`
6. Copy values into root `.env`:
   ```
   X_CLIENT_ID=...
   X_CLIENT_SECRET=...
   X_REDIRECT_URI=http://localhost:3000/api/connections/x/callback
   ```
7. `make restart`
8. In the app: **Connections → Connect X** → OAuth consent → you're in.

Then any commit detail page has a **Publish** card that posts to the connected X account (now or scheduled). URLs in the post body are auto-wrapped through `/t/[commitId]` so clicks attribute back.

### C. Tracking base URL — for production

In dev, tracking links use `http://localhost:3000`. In production set:
```
TRACKING_BASE_URL=https://your-domain.com
```
This is the origin baked into `/t/[commitId]` and `/p/[commitId]` URLs that the worker emits when publishing.

### D. LinkedIn publishing — future (P3)

Blocked on LinkedIn Marketing Developer Platform approval (1–4 weeks).
Stubs in `.env.example`: `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`.

### E. Meta / Instagram publishing — future (P3)

Blocked on Meta App Review. Stubs: `META_APP_ID`, `META_APP_SECRET`.

### F. Email — future (P2)

Resend is the target. `RESEND_API_KEY` slot exists in `.env.example`. Not wired yet.

## 4. Environment variables reference

**Auto-generated by `make setup`** (don't touch unless regenerating):
- `BETTER_AUTH_SECRET`
- `KEY_ENCRYPTION_KEY`
- `AGENTS_INTERNAL_TOKEN`

**Match Docker defaults** (fine unless you change ports):
- `DATABASE_URL`, `REDIS_URL`
- `S3_ENDPOINT`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET`
- `POSTGRES_HOST_PORT`, `REDIS_HOST_PORT`, `MINIO_HOST_PORT`, `MINIO_CONSOLE_HOST_PORT`

**You fill (as features unlock):**
- `X_CLIENT_ID`, `X_CLIENT_SECRET` — X publishing
- `TRACKING_BASE_URL` — production deploys
- `RESEND_API_KEY` — future email
- `LINKEDIN_*`, `META_*` — future, after app review

```bash

make stop           # stop docker
make restart        # stop + start
make reset          # DESTROY volumes + reinstall + re-setup

make db-push        # apply schema changes (Drizzle push)

make infra-down     # docker compose down
```

## 6. Architecture

```
apps/
  web/         Next.js 15 App Router — UI, server actions, auth, tracking endpoints (/t, /p)
  agents/      Python 3.12 + FastAPI + LangGraph — planner / content / brand_summarize
  worker/      Node + BullMQ — publish, brand ingest (website + PDF), future analytics polling
packages/
  db/          Drizzle schema + emit() helper + migrations
  shared/      zod schemas + event-type taxonomy (the contract)
```

**Storage:**
- Postgres 16 with pgvector — relational + brand_memory embeddings
- Redis 7 — BullMQ queues
- MinIO — S3-compatible object storage (brand PDFs; images referenced by URL, not re-hosted)

**Auth:**
- Better Auth (self-hosted) with `organization` plugin — multi-tenant orgs, invitations, roles
- AES-256-GCM envelope encryption for BYO keys + OAuth tokens

**Agent orchestration:**
- LangGraph Python graphs (planner: Opus 4.7, content: Sonnet 4.6, brand_summarize: Opus 4.7)
- Agents read BYO keys per-org from `ai_provider_credentials`
- Web calls agents over HTTP with `X-Internal-Token` header

**The 4 core primitives:**
- **Asset** — `assets` table, one per commit
- **Campaign** — `campaigns` + `branches` (Git-style)
- **Event** — `events` table, emitted by every write path
- **Version** — `commits` with `parent_commit_id` and `content_hash`

## 7. Troubleshooting

**Port 5432 already in use**
Edit `.env` → set `POSTGRES_HOST_PORT=5433` and update the port in `DATABASE_URL` + `apps/agents/.env` DATABASE_URL. `make restart`.

**Worker crashes silently on startup**
Almost always a missing dep after I've updated `package.json`. Run `pnpm install` then `make restart`.

**`DATABASE_URL is not set`**
Root `.env` is missing. Either first-time setup didn't finish or someone deleted it. `make env-regen` will restore.

**Better Auth signup fails with column errors**
Schema drift. Run `make db-push` and accept the prompts.

**X connect fails with `x_error=state_mismatch`**
Stale OAuth cookie. Clear `x_oauth_pkce` cookie or all localhost:3000 cookies and retry.

**Agents fail with "No Anthropic API key available for organization …"**
You haven't added a key via UI, and there's no `ANTHROPIC_API_KEY` fallback in `apps/agents/.env`. Do one or the other.

**I see "agents service error: 401"**
`AGENTS_INTERNAL_TOKEN` differs between root `.env` and `apps/agents/.env`. `make env-regen` re-syncs both.
